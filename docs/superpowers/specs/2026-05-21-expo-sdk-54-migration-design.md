# Expo SDK 54 Migration Design

## Goal

Move the `apps/mobile` Expo app fully from SDK 55 to SDK 54 so it runs against the SDK 54 Expo Go iOS app. The project should use one SDK line after the migration rather than keeping SDK 54 and SDK 55 switching logic.

## Current State

- The repository is an npm workspace with the Expo app in `apps/mobile`.
- `apps/mobile/package.json` currently pins Expo SDK 55 packages, React 19.2, and React Native 0.83.
- The app does not have checked-in `ios/` or `android/` directories, so native projects are generated by Expo tooling when needed.
- The app already includes the Reanimated v4 Worklets dependency pair used by recent Expo SDKs.
- The worktree contains unrelated in-progress changes, so the migration must avoid reverting or sweeping those edits into unrelated commits.

## Chosen Approach

Use Expo-managed dependency alignment for a full SDK 54 downgrade:

1. Install the SDK 54 Expo package for the mobile workspace.
2. Run Expo dependency fixing so SDK-bound packages resolve to the SDK 54-compatible set.
3. Update the npm workspace lockfile with the dependency changes produced by the package manager and Expo tooling.

This keeps the dependency set aligned with Expo's SDK compatibility checks instead of hand-maintaining every SDK-coupled package version.

## Scope

The migration will:

- Downgrade the Expo mobile workspace dependency set from SDK 55 to SDK 54.
- Preserve npm workspace dependency resolution and update the root lockfile as required.
- Review SDK-related app configuration and remove default-only Expo config files or implicit package entries only when Expo guidance and diagnostics show they are redundant.
- Keep `react-native-worklets` aligned with `react-native-reanimated` for SDK 54.
- Fix app code only if SDK 54 diagnostics, typechecking, or bundling show a concrete compatibility break.

The migration will not:

- Add SDK version switching scripts or conditional dependency overrides.
- Generate and commit native `ios/` or `android/` projects for this Expo Go-focused change.
- Refactor product features unrelated to SDK compatibility.

## Verification

Verification will cover the dependency and app surfaces affected by the downgrade:

- Run Expo dependency diagnostics and `expo-doctor`.
- Run the repository test and TypeScript checks where available.
- Run an Expo iOS export or equivalent bundle check for the generated-native-project workflow.
- Report any verification step that cannot run in the local environment.

## Risks

- The workspace already has uncommitted product changes, so package and lockfile edits need to be reviewed carefully against that state.
- SDK 54 uses a different React Native and React baseline than SDK 55, so mismatched transitive package versions can surface in diagnostics or bundling.
- Redundant Babel or Metro files are low-risk cleanup only if they remain default-only after inspection.
